# Hostereo Provider

Manage [Hostereo](https://www.hostereo.com) VPS instances, projects and tags through the Hostereo External API.

## Authentication

Create an API key in the Hostereo console under **Account → API Keys** and export it:

```sh
export HOSTEREO_API_KEY="hst_live_..."
```

Keys are **bound to source IP addresses**: allow the public IP of the machine (or CI runner) that runs Terraform.
The key's scopes decide what Terraform can do:

| Scope | Needed for |
|---|---|
| `instances:read` | reading instances, projects, tags, `hostereo_instance` data source |
| `instances:create` | creating instances |
| `instances:write` | resize, power, project/tag assignment, creating/updating projects and tags |
| `operations:read` | waiting for asynchronous operations (create, resize, power, delete) |
| `instances:delete` | `terraform destroy` of instances |

The catalogue data sources (`hostereo_regions`, `hostereo_plans`, `hostereo_images`, `hostereo_applications`) are public.

## Deletion protection

Every instance is **deletion-protected by default** on the server. The provider exposes this as the read-only
`deletion_protection` attribute and never changes it. To destroy an instance with Terraform, first turn protection off in
the Hostereo console (instance **Overview → API delete protection**), then run `terraform destroy`.

## Secrets and state

- `api_key` is sensitive and is never written to state or logs.
- The instance `password` is **write-only** (Terraform 1.11+): it is sent once at creation and never stored in state or plan.
- The provider does not read application credentials or console URLs, so none end up in state.

```terraform
terraform {
  required_providers {
    hostereo = {
      source  = "interhostnetworks/hostereo"
      version = "~> 0.1"
    }
  }
}

# The API key is read from HOSTEREO_API_KEY. Keys are IP-bound: allow the
# address Terraform runs from (Hostereo console → Account → API Keys).
provider "hostereo" {}
```
